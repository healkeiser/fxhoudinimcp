## Know which space you are in

Copernicus is not a 2D canvas with one coordinate system. Getting the space wrong
is the most common reason a setup looks right and lands wrong
(`copernicus/spaces`):

- **Buffer** is the sample layout in memory, positioned by the data window.
- **Pixel** is a canonical pixel-sized area with its origin at the pixel's lower-left, positioned by the display window.
- **Texture** maps 0 to 1 across the data window and Buffer, so it stretches.
- **Image** maps -1 to 1 across the display window and preserves pixel aspect. The node preview thumbnail is this space.
- **Local** maps -(w/2, h/2) to (w/2, h/2) across the display window in world units, preserving aspect.

Data window and display window are different things. A node whose result is
mysteriously cropped or offset is usually a window issue rather than a maths one.

## Outputs and the display flag are not the SOP story

- A COP node can have **multiple outputs**. Which one the Scene View shows is chosen per node: click the output name at the node's bottom right, or RMB > Flags > Output for View. That choice does not change what the node outputs downstream.
- From a SOP network you are looking at a copnet. To pick which COP output reaches the Scene View from there, turn on **Single Output** on the COP Network node and set **Output**.
- The viewer output is a pixel representation of a voxel grid, and Copernicus applies a default visualizer to make data legible, so **what the viewport shows is not always what the data is.** Height displays as heightfields in the Scene Viewer and hillshades in the Composite Viewer.

## Practical

- Inspect actual pixel values rather than trusting the display: display flag on, then RMB > **Inspect** in the Composite Viewer and hover.
- `copcache -c` in the textport clears GPU and memory usage, and recooks anything displayed. This is the first thing to try when GPU memory has run away.
- Importing a SOP with sopimport places geometry in **world space**. To frame it into the canonical camera view, use rasterizesetup with the geometry in its `source` input.
- Drag COP nodes and cameras into the Scene Viewer to look through them.

## Order of work

1. `set_current_network` into the COP network, then bring data in: file, or sopimport plus rasterizesetup for geometry.
2. Decide the working resolution and window before building the chain. Changing it later re-frames everything downstream.
3. Build the chain, keeping named null nodes as labelled waypoints.
4. Inspect real pixel values at each milestone rather than judging by the visualizer, and `capture_screenshot` to look.
5. Write with rop_image, and cache upstream of anything expensive so look iteration does not recook it.
