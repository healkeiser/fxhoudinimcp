## Attributes, and the precedence that explains most surprises

Attributes live on four levels, and when the same name exists on two of them the
**lower level wins** (`model/attributes`):

**vertex** overrides **point**, which overrides **primitive**, which overrides
**detail**.

A value you set that appears not to take effect is usually being overridden from
below. Check the level before changing the value, and use attribpromote
deliberately rather than as a fix for something you have not diagnosed.

## Select by attribute instead of writing a wrangle

Most SOPs have a **Group** field, and it takes attribute expressions, not just
group names: `@foo>5` in a Group field selects every component whose `foo`
attribute exceeds 5. A great many wrangles exist only because someone did not
know this. Reach for a group pattern before VEX, and for groupexpression when the
condition needs to be stored.

## Packed primitives: the memory model

Packed primitives **express a procedure to generate geometry at render time**.
They carry either geometry in memory, a reference into other geometry, or a path
to a file on disk, and viewport, renderer and solvers all know how to work with
them efficiently (`model/packed`).

The consequences worth internalising:

- **Packed primitives cannot be edited.** They are lightweight references. To change one: unpack, modify, and repack if you still want it packed. A chain that unpacks early throws away the reason to pack at all.
- **Copying a packed primitive copies the reference**, not the geometry. That is the entire memory saving, and it is why copytopoints with Pack and Instance is cheap while duplicating real geometry is not.
- Pack anything that will not change. Non-deforming RBD pieces are the standard case.

## Copying versus instancing, which are not the same thing

- **copytopoints** makes real (possibly packed) copies in the SOP graph. You can see them, group them, simulate them.
- **Instancing replaces an object with another at render time.** The instanced geometry costs no memory and does not slow the viewport, because it does not exist until the render. The price is that **you cannot see it while you work** (`copy/instancing`).
- So: proxy in the viewport, heavy geometry at render, is the point of instancing, not an optimisation you bolt on.
- A delayed load shader keeps the instanced geometry on disk instead of in the scene, which is how a meadow of trees stays a small hip file.

Choose deliberately: copytopoints when downstream nodes or a sim must see the
copies, instancing when only the renderer needs them.

## Example chains (no VEX)

- AC unit: box → polybevel → boolean (circle cutout) → scatter → small grid → copytopoints
- Table: box (top) + box (leg) → copytopoints (4 corners) → merge
- Terrain: grid → mountain → scatter → copytopoints
- Pipe: circle → sweep along curve → resample → fuse
- Window: grid → polyextrude (inset) → boolean (panes) → xform

Two modelling approaches, and SideFX documents them separately: box-up starts
from a primitive and extrudes, splits and bevels it; curve-up builds construction
curves and makes surfaces from them with revolve or skin. Pick one per element
rather than mixing halfway through.

## VEX specifics (only once no SOP fits)

- Channel references: prefer relative paths. The create_wrangle response includes channel_ancestors showing what each ../ level resolves to, so use it rather than counting depth by hand. Absolute paths break when nodes are renamed or moved.
- Detail-mode wrangles can create geometry with addpoint()/addprim() and need no input geometry.
- ch()/chi()/chf() return 0 silently when the path is wrong.

## Failure signatures

- **Value set but nothing changed.** Attribute precedence: something on a lower level is overriding it.
- **Edit to a packed primitive does nothing.** Packed prims are immutable references. Unpack first.
- **Copies present in SOPs but absent from the render, or the reverse.** copytopoints versus instancing confusion.
- **Scene file enormous.** Real geometry where packed primitives or delayed load would do.
- **Group field seems to ignore the pattern.** Wrong component level for the attribute named in it.

## Do not loop

If something fails twice, STOP and change strategy: validate_vex for compilation
errors, execute_python to inspect live values, find_error_nodes for upstream
errors. Do not re-run get_geometry_info hoping for a different answer.
